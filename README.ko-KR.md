# paper-research-agent

할루시네이션 없는 논문 탐색·정리 에이전트.

LLM이 지어낸 논문을 걸러내고, **전문을 실제로 확보한 논문만** 요약해 옵시디언 노트와 Zotero 파일로 저장합니다.

```bash
git clone https://github.com/<your-account>/paper-research-agent.git
cd paper-research-agent
python server.py     # 또는 start.bat 더블클릭
```

![결과 화면](paper-research-agent/docs/02-results-light.png)

*검증 통과·불확실·확인 실패·무관이 한눈에 구분됩니다. 실패한 것도 이유와 함께 남습니다.*

---

## 왜 만들었나

LLM에게 "~에 대한 논문 찾아줘"라고 하면 나오는 목록 중 일부는 실제로 존재하지 않습니다.

더 위험한 건 그다음입니다. 존재가 확인된 논문이라도 전문 없이 "요약해줘"라고 시키면 모델이 제목과 저자만 보고 그럴듯한 내용을 지어냅니다. 그리고 "존재는 확인됐다"는 신뢰 때문에 사용자가 **더 쉽게 속습니다.**

이 도구는 두 지점을 모두 막습니다.

## 원칙

### 1. 검증 우선

식별자(DOI/arXiv ID)가 있어도 그것만으로는 부족합니다. 진짜 DOI를 가져다 붙이고 제목·저자를 바꿔치기한 위조가 실제로 있기 때문에, 항상 **식별자 + 저자 + 연도**를 함께 확인합니다.

### 2. 전문 기반 요약만

전문을 확보한 경우에만 요약합니다. 초록만 있으면 `abstract_only`로 **명확히 구분해** 표시하고, 방법 정보가 없다는 걸 노트 상단에 경고로 띄웁니다.

### 3. 투명한 실패 처리

못 찾은 것, 요약 못 한 것, 검증 실패한 것을 전부 보여줍니다. **조용히 빼먹지 않습니다.**

### 4. 모델 독립적

OpenAI · Anthropic · Gemini · Ollama를 별도 설치 없이 지원합니다.

## 검증 판정 규칙

이 도구에서 가장 중요한 부분입니다.

| 상태 | 의미 | 언제 |
|---|---|---|
| `verified` | 식별자 + 저자 + 연도가 인덱스에서 함께 일치 | 통과 |
| `uncertain` | **판정 불가** | API 장애, 미색인, 식별자 부재 |
| `not_found` | 인덱스가 명시적으로 "없다"고 답함 | 조회 실패 확정 |

**`uncertain`과 `not_found`를 구분하는 게 핵심입니다.**

- API가 죽어서 못 찾은 걸 `not_found`로 처리하면 → 네트워크가 끊긴 날 **모든 논문이 가짜로 찍힙니다**
- 색인에 없다고 `not_found`로 처리하면 → **비영어권·인문학·오래된 논문이 몰살당합니다**

그래서 "확인 못 함"과 "가짜"를 절대 섞지 않습니다.

반대로 **식별자는 실존하는데 제목·저자가 어긋나는 경우**(`mismatch`)는 단순 부재보다 **강한 날조 신호**로 취급해 `not_found`로 판정합니다.

## 설치

### 요구사항

- **파이썬 3.10 이상**
- **LLM 하나** — Ollama(무료·로컬) 또는 API 키 중 택 1
- 인터넷 (OpenAlex · Crossref · arXiv · Unpaywall — 전부 무료, 키 불필요)

### 실행

| OS | 방법 |
|---|---|
| 윈도우 | `start.bat` 더블클릭 |
| macOS | `chmod +x start.command` 후 더블클릭 |
| 리눅스 | `bash start.command` |

런처가 파이썬을 찾고, 없는 패키지를 설치하고, 서버를 켠 뒤 브라우저를 엽니다. 처음 한 번만 설치가 돌고 다음부터는 바로 열립니다.

직접 실행하려면:

```bash
pip install -r requirements.txt
python server.py          # 웹 UI
python main.py "질문"      # CLI
```

기본 포트 8765가 사용 중이면 자동으로 다음 포트로 넘어갑니다.

### 첫 설정

브라우저가 열리면 **이메일**과 **저장 경로** 두 칸만 채우면 됩니다.

이메일은 OpenAlex·Crossref가 요청 한도를 늘려주는 데 쓰이고, Unpaywall은 이게 없으면 동작하지 않습니다.

---

## 왜 브라우저만으로는 안 되나

순수 HTML 파일로 만들면 세 가지가 막힙니다.

1. **PDF를 못 받아옵니다** — 브라우저는 CORS 때문에 임의 서버의 응답을 읽지 못합니다. OA PDF는 수백 개 리포지토리에 흩어져 있고 그쪽이 CORS 헤더를 보낼 이유가 없습니다. 전문을 못 구하면 원칙 2가 무력화됩니다.
2. **파일을 못 씁니다** — 브라우저는 옵시디언 vault 경로에 직접 저장할 수 없습니다.
3. **키가 노출됩니다** — 브라우저에 API 키를 두면 확장 프로그램과 개발자도구에서 읽힙니다.

로컬 서버는 이 셋을 모두 해결하면서도 외부로 나가는 데이터가 없습니다. 기본으로 `127.0.0.1`에만 바인딩합니다.

## 주요 기능

### 시드 논문

"이건 확실히 관련 있다" 싶은 논문을 DOI나 제목으로 넣으면:

- 그 논문의 **실제 학술 어휘**를 뽑아 검색어에 씁니다 (`organizational adoption`, `firm performance` 같은 분야 용어)
- **참고문헌과 피인용 논문**을 따라갑니다 — 키워드 검색이 못 찾는 논문이 여기서 나옵니다

제목이 충분히 안 맞으면 **추측하지 않고** "못 찾았다"고 합니다. 시드가 틀리면 탐색 전체가 어긋나기 때문입니다.

### 전문 확보

```
CORE (텍스트 직접) → OpenAlex → arXiv → Unpaywall → Semantic Scholar
```

CORE는 링크가 아니라 **전문 텍스트를 API 응답에 직접** 담아줍니다. 받으면 다운로드와 PDF 파싱을 통째로 건너뛰어 실패할 수 있는 단계가 두 개 사라집니다. 기관 리포지토리를 1만 곳 넘게 수집해서, 페이월 논문의 저자 최종본이 여기서 나오는 경우가 많습니다.

PDF 링크가 랜딩 페이지를 가리키면 `citation_pdf_url` 메타 태그를 찾아 실제 PDF로 한 번 더 시도합니다.

### 인용 대조

요약이 인용한 문장이 **원문에 실제로 있는지** 문자열로 대조합니다. LLM을 쓰지 않습니다.

| 페이지 | 인용 | 대조 |
|---|---|---|
| p.1 | we surveyed 312 firms across manufacturing | ✅ 1.0 |
| p.7 | achieves perfect accuracy on all benchmarks | ⚠ 0.31 |

**실패한 인용은 지우지 않고 남깁니다.** 조용히 지우면 사용자가 요약이 100% 검증된 것처럼 착각합니다.

### 진단 표

전문을 못 구한 이유를 원인별로 집계합니다.

| 원인 | 건수 |
|---|---|
| 무료 사본 없음 | 2 |
| PDF가 아님(랜딩/페이월) | 1 |

원인마다 대응이 다르기 때문에 구분합니다. 무료 사본 없음이 대부분이면 소스를 늘려야 하고, PDF가 아님이 대부분이면 랜딩 페이지 처리를 손봐야 하고, 다운로드 실패가 대부분이면 리포지토리가 봇을 차단하는 중입니다.

### 옵시디언 그래프

네 종류 엣지를 만듭니다.

- **논문 ↔ 논문** — 수집한 논문들 *사이의* 인용만. 참고문헌 전체를 링크하면 존재하지 않는 노드 수백 개가 생겨 그래프가 먼지구름이 됩니다
- **논문 ↔ 키워드** — 2편 이상이 공유하는 어구만 허브 노트로 만듭니다
- **논문 ↔ 저널**
- **논문 ↔ 세션 MOC**

frontmatter의 `keywords` · `cites` · `cited_by`로 Dataview 질의가 가능합니다.

### 원문 확보 토글

`원문 받아서 요약`을 끄면 검색·검증·관련도까지만 하고 목록을 냅니다.

| | 켰을 때 | 껐을 때 |
|---|---|---|
| 하는 일 | PDF 확보 + 요약 + 인용 대조 | 검색 + 검증 + 관련도 |
| 논문당 | 최대 4분 | 수 초 |
| 노트 | 요약 포함 | 메타데이터 + OA 상태 |

노트에는 `전문 확보를 끄고 실행함 (다시 켜서 재실행하면 요약됩니다)`로 남습니다. 실패가 아니라 선택이라는 걸 구분합니다.

### 중단과 재검색

결과가 시원찮으면 **중단**을 누르세요. 여기까지의 결과가 그 폴더에 저장되고, **즉시** 새 검색을 시작할 수 있습니다.

- 대기 중(arXiv 3초, 재시도 백오프 최대 30초)에도 즉시 반응합니다
- 중단하면 인용 관계 조회처럼 무거운 작업은 건너뜁니다
- 폴더가 분리돼 있어 이전 작업이 저장되는 동안 새로 시작해도 안 섞입니다

### Zotero 내보내기

실행할 때마다 `exports/`에 `.ris` · `.bib` · `.csv`가 생깁니다.

검증 정보가 태그로 함께 갑니다.

```
KW  - verify/verified
KW  - summary/abstract_only
KW  - method/missing
```

Zotero에서 `summary/abstract_only` 태그로 걸러내면 **전문을 더 구해야 하는 논문**이 바로 나옵니다.

## 산출물

**검색할 때마다 별도 폴더**가 생깁니다. 같은 폴더에 계속 쌓이면 어느 논문이 어느 질문에서 나왔는지 알 수 없습니다.

```
vault/
├── 2026-08-21_1430 경영학 AI agent 활용 사례/
│   ├── _경영학 AI agent 활용 사례.md    세션 요약 (맨 위에 옴)
│   ├── _실행 로그 2026-08-21_143012.md
│   ├── papers/
│   │   └── Kim (2024) Organizational adoption of AI agents.md
│   ├── keywords/
│   │   └── firm performance.md
│   └── exports/
│       ├── 경영학 AI agent 활용 사례.ris
│       ├── 경영학 AI agent 활용 사례.bib
│       └── 경영학 AI agent 활용 사례.csv
└── 2026-08-21_1512 RAG 환각 억제 기법/
    └── ...
```

결과가 마음에 안 들면 **중단** 버튼을 누르세요. 여기까지의 결과는 그 폴더에 저장되고, 곧바로 새 검색을 시작할 수 있습니다. 폴더가 분리되어 있어 이전 작업이 저장되는 동안 새로 시작해도 섞이지 않습니다.

노트 frontmatter에 신뢰 수준이 기록됩니다.

```yaml
verification_status: verified
verified_by: ["openalex", "crossref"]
summary_depth: full_text        # full_text | abstract_only | no_summary
oa_status: free
tags: [paper, verify/verified, summary/full_text, tier/top]
```

vault에서 이렇게 걸러낼 수 있습니다.

- `tag:#summary/full_text` — 믿고 인용해도 되는 것
- `tag:#summary/abstract_only` — 전문을 더 구해야 하는 것
- `tag:#verify/uncertain` — 직접 확인이 필요한 것

## 설정

`config.yaml`의 주요 항목입니다. 대부분 UI에서 조절할 수 있습니다.

```yaml
llm:
  model: "ollama/llama3.1"      # 또는 openai/gpt-4o, anthropic/claude-..., gemini/...

search:
  target_verified: 5             # 검증 통과 논문이 이만큼 모이면 중단
  max_rounds: 3
  verify_workers: 4              # 동시 검증 수

verify:
  mode: fast                     # fast: 한 곳에서 확인되면 통과 (권장)
                                 # strict: 모든 인덱스 교차 확인 (논문당 3초+)
  title_similarity_threshold: 0.70

relevance:
  min_score: 2.0                 # 0~5. 낮추면 더 많이 통과

summarize:
  abstract_fallback: true        # 전문 없으면 초록으로 정리
  max_input_chars: 60000         # 로컬 Ollama면 20000~25000 권장

graph:
  enabled: true
  citation_edges: true           # 느리면 끄세요

export:
  formats: ["ris", "bibtex", "csv"]
```

API 키는 `config.yaml`이 아니라 `.env`(권한 600)에 저장됩니다.

## 테스트

```bash
python -m pytest tests/ -v
```

**107개 테스트.** 확인하는 건 "코드가 돌아가는가"가 아니라 **"판정이 옳은가"**입니다.

- API 장애가 `not_found`로 새지 않는가
- 미색인 논문을 가짜로 죽이지 않는가
- 지어낸 인용을 잡는가 — 그리고 **진짜 인용을 실수로 떨어뜨리지 않는가**
- 초록에 없는 방법을 지어내면 걸리는가
- 저자명을 틀린 순서로 뒤집지 않는가
- 무관한 논문이 그래프에서 고립되는가
- 검색 두 번이 같은 폴더를 쓰지 않는가
- 중단이 1.2초 안에 반응하는가

## 알려진 한계

- **경영학·사회과학은 OA 비율이 낮습니다.** Elsevier·Emerald·Wiley 페이월 비중이 커서, API를 더 붙여도 전문 확보율이 크게 오르지 않습니다. 진단 표로 실제 원인을 확인하세요.
- **구글 스칼라는 자동화할 수 없습니다.** 공식 API가 없고 스크래핑을 차단합니다. 대신 수동 재시도 경로가 있습니다:
  ```bash
  python main.py --retry-doi "10.1016/j.x" --retry-pdf "<PDF 주소나 파일 경로>"
  ```
- **저자명 성/이름 구분**은 Crossref 데이터에서만 정확합니다. OpenAlex는 나눠 주지 않아서, 공백만 있는 이름은 **추측하지 않고 원문 그대로** 둡니다 (영어권은 뒤가 성, 한국어 로마자는 앞이 성이라 판별 불가).

## 참조

검증 아키텍처 일부는 [Academic Research Skills](https://github.com/Imbad0202/academic-research-skills) (CC BY-NC 4.0)의 설계 판단을 참조했습니다. 코드를 복사하지 않고 아래 아이디어를 재구현했습니다.

- 교차 인덱스 검증 + 3-상태 판정
- precision-over-recall — 미색인을 부재의 증거로 쓰지 않는다
- 장애 래치로 API 장애와 논문 부재를 분리
- 유사도 임계값·재시도 상수를 공유 모듈 한 곳에 고정
- 스로틀 측정에 `time.monotonic` 사용 (`time.time`은 NTP-unsafe)
- 인용 앵커를 25단어로 제한 (길수록 추출 노이즈로 오탐 증가)
- Anti-Leakage — 모델이 빈칸을 기억으로 채우는 대신 `[근거 없음]`을 찍게 함

원본은 비영리 라이선스입니다. 설계 아이디어에는 저작권이 미치지 않지만, 원본 코드나 프롬프트를 직접 사용할 경우 저작자 표시와 비영리 조건이 적용됩니다.
